# Commons CORE

*What a commons holds of itself: one repository, in the grammar of MODEL, on the near future.*

## 1 · Goal

A commons needs one place where it holds what it is heading for, in words people and agents read alike. That place is its CORE: one repository with its models, the grounding of them, its path through time and the views it renders from them. The CORE learns from reality at the start and then leads it, giving it orientation; it is a model drawn with as few strokes as needed, never the world and never a system of record. It orients itself on the Commons by installing its models, following their versions and departing from them only visibly, in the runtime it builds from them. This specification decides one thing for its reader: **whether a repository is a well-formed CORE of a commons**. How certain its statements are is specified in `core-knowledge`, and what it renders in `core-views`.

## 2 · Boundary

**Belongs here:**
- the identity and settings of a CORE;
- its models: the runtime, the models it installs and its emulations; installing them and building from them;
- its areas and where every part lives;
- the near future it holds, and its history;
- its lifecycle;
- the party register;
- the patterns it installs, and its own;
- its bill of materials, single-level;
- world COREs.

**Does not belong here:**

| Matter | Where it belongs |
|---|---|
| the grammar of the records | MODEL |
| how certain a statement is; `knowledge/` | `core-knowledge` |
| the blueprint definition and the views | `core-views` |
| how the commons works on itself: items, Bodies at work, decisions, rhythms, boot as a conversation | FLOW |
| what a model holds, a catalogue, its depth | MODEL |
| a model's release and its bill; the hull's release | LIBRARY |
| the form of patterns, their release, the extract and the full form of the agents' index | LIBRARY |
| connections across COREs and over time; the graph's sources and runs, answers from it, nothing written back, and what a release may disclose; a bill resolved over more levels, and where a part is used | GRAPH |
| machine access | MCP |

**Touches** the specifications named in the front matter.

## 5 · Structure

The schema is `schemas/core.schema.json`. Its root is `.commons/commons.yml`; its `$defs` hold `stage`, `event` and `person` (with `people`, the party register).

The event kind `not-selected` and a decision's `activates` block are retired (decision 33): the merge into `main` is the decision. The schema keeps them only so that recorded events validate as history (R12), and no tool writes them.

| Field of `commons.yml` | Holds |
|---|---|
| `id`, `name`, `code` | the stable id; the display name; the commons code of the Body handles |
| `purpose` | the commons' purpose in one sentence, in the words of its accountable people, never an agent's (`flow-bodies` R18); a gap while unstated (R41) |
| `holder` | who holds this CORE, where it is not the commons itself |
| `perspective` | `observed` where the CORE is kept by an outside observer; `own` when absent. Holding a CORE is no mandate to observe |
| `instance_type` | `commons`, or `world` for a world CORE |
| `slice`, `world`, `world_of`, `as_of`, `target` | a world's horizon in years, its name in its set, the id of its CORE, the date of this generation; **`target` = the year of `as_of` + `slice`**, written only for display |
| `language`, `languages` | the commons' own language; further languages of its views |
| `structure` | the version of the structure definition it is on |
| `models` | each with `id` and `version`; at most one `primary`, never the Commons model; a model as `<library>/<model>`; `extensions` is its earlier key |
| `libraries` | `{<id>: <owner>/<repo>}` for every library it installs from |
| `half_life` | `{<kind>: <days>}`, the half-life of a kind of record or claim where the commons sets its own (`core-knowledge` R21 and part 5) |
| `library_clones` | `{<id>: <path>}`, where the last clone of a library it names lies, relative to the CORE; `../library` where none is named (R40) |
| `locations` | structure keys moved from their default place |
| `order` | `{<family>: [<stream>, …]}`, the commons' own order of its streams in the offer's form, to place its own or re-order what it changed; without it, the order its models deliver (CORE-VIEWS R21) |
| `sources`, `mcp` | the repositories it draws on; its MCP endpoints |

**The structure definition** is the Commons model's `structure.yml`, pinned by version. It gives every structure key its default location and its earlier ones. `access.yml` stays beside `commons.yml` as policy.

**The lock** is `.commons/lock.yml`, generated at install and never edited: `specs` as `{path, origin, version}` (R26), `models` as `{id, variant, version, origin, record, installed, served}`, `variant` only for a variant (R39), `patterns` as `{path, origin, record}` (R28).

**The reading of `federation.mcp`** is `.commons/federation.yml` (`$defs/reading`), written at each contact from what `federation.mcp` answers and never edited: `from` (the endpoint, `access.yml`'s `federation`, `mcp` R24), `read_at` (a date or time), `generator` (what took it) and `shells`, all six shells of MODEL (SEED, CORE, PEER, OPEN, DOCK, ROAM), each with the offer every envelope carries (`mcp` R28, `$defs/offered`): `reads`, `writes`, `budget`, each of its limits a number, and `sources` where narrowed. It holds no user, no account and never what one caller `gets`; other metadata is tolerated. Its age is `read_at`, read beside it, never a deadline. The agent file asks `federation.mcp` at the address `access.yml` names for it, apart from the commons' own MCP.

**The bill of materials** is generated by `tools/check_core.py --bill` and never kept as a file. Only a finding on what it lists withholds it: on the lock, the installed copies, among them the gate's checks of a copy (LIBRARY R9), and the sources read; every other finding stands beside it, whatever a reader filters. It names its `generator` and the `rev` of the CORE it was generated from, and `read_at` where the CORE's files differ from that commit, as a cut of GRAPH names a source. Each line has `part` and `usage` and, where its source gives them, `origin`, `record`, `licence` (that of the release record, `library` R11), `class`, `access` and `holder`. In a release's part `<library>/<id>@<version>#<part>`, what precedes `#` is the release as the library's index names it, and `record` its digest there; the part's own files are no line of this bill (`library` R3).

| Usage | `part` | Generated from |
|---|---|---|
| `installed` | a specification as `<id>@<version>`; a part of a release as `<library>/<id>@<version>#<part>`, an extract's id being `patterns` (`library` part 5) | the lock |
| `served` | a source of a maker's register that its MCP serves under a grant, as `{repo: owner/repo, source: <id>}` (`graph` R2, `mcp` R19) | the lock's `served` |
| `read` | a system as `fabric/systems.yml#<id>`; another CORE as `owner/repo@rev` | `fabric/systems.yml`; the graph register's entries of kind `core` |

A record of the runtime is the commons' own and no line: where-used resolves its `origin` (`graph` R27), a withholding reaching it so (`library` R18), and its departure is derived on request (R6). A commons pins exact releases and takes up a newer one only by decision (R28), so no version range is ever resolved; every revision of `main` is an approved configuration, because `main` changes only by a merge on decision (R10); and there is one bill, read at a revision, whatever it is read for.

**The repository name**, written out: `[holder.][world.][commons][.slice].core`, for example `[commons].core`, `[commons].10.core` and `[world].[commons].20.core`. The holder is omitted where the commons holds its own CORE, and the slice is omitted at 0. A name is displayed as *[commons] CORE +10*; the `+` appears only in the display, because repository names do not allow it.

**Models** live in `models/` (structure keys `models`, `runtime`, `commons`, `emulation`, `loops`, `state`). The runtime is `models/runtime/`: the nine element folders, `loops/` and `state/`. The models a CORE installs lie whole and read-only in `models/commons/<library>/<model>/`, a variant in `models/commons/<library>/<model>/<variant>/`, the Commons model in `models/commons/<library>/commons/`, and their specifications are read in that copy (R26, R39). Each emulation is `models/emulation/<name>/`, with `model.yml` (MODEL part 5) and, where it is tried, its own `state/`. One tool, `tools/build.py`, builds the runtime and any emulation from the installed models and the commons' own records, and at a take-up moves the runtime whole, its records and their origins unchanged, to `models/emulation/<name>/` and the emulation into its place, on the branch whose merge is the decision (R6); a commons grows into the next variant by this take-up, never by an update of the variant it has (R39). A Post lies in its Body's folder, `bodies/` (structure key `posts`). Every model has this one layout, so one reader reads them all, and a release is an emulation's folder with its release record (LIBRARY). The earlier locations are `registry/`, `operations/loops/`, `operations/loops/_state/`, `extensions/` and `offer/`; `operations/loops/_contract.yml` and `operations/rhythms.md` dissolve. A change of the runtime is a change of `main` by decision (R10), made as work in the Model Workshop (FLOW).

**A model in the making** is an emulation (R6), a domain's variants among them (MODEL R30); it is released only from there, through a library's gate (LIBRARY R19), by a `[domain].core` for its domain, by `commons.core` for the Commons model, and by any CORE that offers what it has learned.

**Specifications** live in `specs/` at the root (structure key `specs`): `<id>.md`, with `schemas/`, `tools/`, `examples/<id>/` and `glossary/` beside them. Those of the Commons model and of every other installed model are read in its copy, `models/commons/<library>/<model>/specs/`, and never copied here; at tier 3 the key may point to a LIBRARY or GRAPH repository of its own (#79 D1), and `<spec>#R<n>` resolves the same way.

**Patterns** live in `patterns/` (structure key `patterns`). An installed extract sits read-only in `patterns/commons/<library>/`: the pattern files at their release paths, and `index.jsonl`, whose first line has `kind: index` and repeats the `release`. LIBRARY specifies the extract and the index. A commons' own patterns are files anywhere in `patterns/` outside `patterns/commons/`, read by their `id`; an own pattern has `id` and, where it adapts an installed one, `origin: {id, release}`. The source of an extract holds its stock as its own patterns and installs none of it. The extract holds its release record `release.yml` (`library` R3). The generated lock records each extract under `patterns` as `{path, origin, record}`: the folder under `patterns/commons/`, the library release as `owner/repo@rev`, and the record digest the library's index gives for that release. Each installed extract is one entry of the CORE's graph register, pinned by the lock (GRAPH).

**The graph** lives in `graph/` (structure key `graph`): its register `graph/sources.yml`, which the commons writes, and its run packages in `graph/runs/<run>/`, which only the Graph Engine writes (GRAPH R1).

**The party register** is `people.yml` at the root (structure key `people`). It holds `people`, each with `id`, `name`, `role` and an optional `contact`.

**The agent file** is `AGENT.md` at the root. Its generated part ends where the line `## Own guidance` begins, and its provenance record is `.provenance/agent/manifest.json`: `definitions`, `inputs` with their hashes, and `output`, the hash of the generated part. What each generated part carries is the generator's, `tools/make_agent.py`, released with the Commons model. In a CORE that is its commons' own, part 1 opens with the task it takes on with the Commons model, the commons' `name` in place of [commons], else a gap: *The [commons] CORE enables [commons] to keep value creation relevant. As a commons, [commons] is shared value creation. The [commons] CORE is a cybernetic model of shared value creation.*; the line *What a commons is* follows it from the definition pattern (R28), and the purpose stays the commons' own (`flow-bodies` R18); an observed twin, a world and a game open with their kind line. The own guidance may hold the commons' voice, its domain conventions, research method, quality bar and own practices; it never restates a requirement, carries dated state, names a person outside the register or carries another commons' content. A hand-kept `AGENT.md` is read as unmigrated (R4).

## 6 · Checks

`tools/check_core.py <core>` reads one CORE. It reports **fail**, **should** or **gap**, and exits with 1 only on a fail. It reads the structure definition of the declared version from the CORE's installed copy of the Commons model, else from the copy beside the tool, and reports a gap where none is at hand. With `--spec core`, `core-knowledge` or `core-views` it runs the checks of that specification only; the check ids are unique across the three, and `review` is the keyword of SPECIFICATION R10, not a check of the tool.

## 7 · Example

  - {id: commons-library/commons, version: 0.3.0}

**Complete:** [a CORE of a neighbourhood tool library](examples/core/tool-library.core/.commons/commons.yml), with its runtime, knowledge, lifecycle, party register and views; `check_core.py` reads it with 0 fail.

**Patterns:** [an installed extract, the library fixture's release copy byte for byte](tools/tests/core/good/patterns.core/patterns/commons/demo-library/release.yml), beside an own pattern made from it, passes with 0 fail; the same extract with one pattern's text changed after release, its index and lock unchanged (`bad/patterns-body.core`), fails.

A served source its maker's register does not hold, a model installed without its entry in the lock, a bill kept as a file, and a record whose `origin` names a version the CORE does not install each fail, and the last has no bill (`bad/bill-*.core`).

**Agent file:** [a CORE](tools/tests/core/good/agent.core/.commons/commons.yml) whose `AGENT.md`, generated by `make_agent.py`, has its provenance record, a pointer file and a folder note, each in its own wording, passes with 0 fail; a missing part, a hand edit, an input changed without regeneration and a folder note without the pointer each fail (`bad/agent-*.core`).

**Reading of `federation.mcp`:** [a reading](tools/tests/core/good/bill.core/.commons/federation.yml) of all six shells, as the reference producer emits the offer over [the MCP example's `access.yml`](tools/tests/mcp/access.yml) (`serve_mcp.offer`), passes, and so does one with other metadata or an unquoted time; one that names a user's account, holds what one caller `gets`, has no `read_at` or one that is no date, holds no offer or a shell with users, in it or in its budget, or the old `read`/`write`, or lacks a shell, fails; one read from another address than `access.yml` names is a should naming both.
